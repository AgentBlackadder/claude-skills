# Stuck patterns

Common shapes of being stuck, each with how to spot it and the smallest move
that usually shifts it. Diagnose first. The wrong fix for the right person
wastes the moment.

## Perfectionism

**Sounds like:** "I'll start when I can do it properly." "It has to be good."
Endless outlines. Research that never ends.

**What's happening:** expectancy is low, because the bar is set where success
is unlikely, so starting feels like signing up for failure.

**Move:** write `DRAFT 0` at the top and aim for the worst acceptable version.
Mark gaps with `[TK]` (to come) rather than stopping to fill them. Editing
something bad is far easier than creating something good from nothing.

## Overwhelm

**Sounds like:** "There's too much." "I don't know where to begin." Frozen in
front of the list.

**What's happening:** the whole backlog is being felt at once, so every task
carries the weight of all of them.

**Move:** hide the list. Pick **one** item, preferably the smallest that matters
at all, and do its first action. Only one task is ever done at a time anyway.
Plan the rest later with `akrasia-plan`, after one win.

## Ambiguity

**Sounds like:** "I'm not sure what they want." "I need to think about it more."

**What's happening:** the task isn't yet a task, it's a decision in disguise,
and deciding is uncomfortable.

**Move:** write the decision as a question, then answer it provisionally:
"Assume ___ for now; revisit if wrong." Or turn the first action into asking
for clarification: send the message now.

## Fear of judgement

**Sounds like:** "What if it's not good enough?" Avoiding sending, submitting or
showing.

**Move:** separate making from showing. Today's task is to make it, not to send
it. Picture one friendly reader rather than the harshest one. If showing is the
sticking point, set a small, fixed show date with a trusted person
(`akrasia-commit`).

## Boredom

**Sounds like:** "It's so tedious." Tasks that need doing but mean nothing.

**Move:** temptation bundle, timer race ("how many in 15 minutes?"), or batch
several dull tasks into one short block with a reward after it. Also ask
whether it can be delegated, automated or dropped (`akrasia-contrast`
feasibility check).

## Resentment

**Sounds like:** "Why do I even have to do this?" Tasks imposed by someone else.

**Move:** name the resentment, then find the part that serves the user (the
relationship, the reputation, getting it off the plate). If there's no such
part, that's a conversation to have with the person who set the task, not a
focus problem.

## The "just before" dodge

**Sounds like:** "I'll start right after I check email / get a coffee / tidy
up."

**Move:** swap the order. The two-minute first action comes **before** the
ritual, and the ritual becomes the reward. An if-then helps here: "If I think
'right after…', then I do the first action first."

## Structured procrastination: using the avoidance

The philosopher John Perry noticed that procrastinators often do a lot, just not
the thing at the top of the list. His "structured procrastination" keeps a
genuinely important but less urgent task near the top, so avoiding the top task
still produces useful work. Use it only as a fallback when the ONE THING truly
won't move today, and not as a daily habit, or the ONE THING never happens.

## When nothing works today

Some days the right move is to stop fighting: rest, sleep, eat, move. Then plan
tomorrow's first action now (`akrasia-plan`) and close the day with that one
line written. Tomorrow starts with a decision already made.
